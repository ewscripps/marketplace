A-02 | P0 | high | Competing Requirements / D13 fidelity | EDMV3-37, EDMV3-30, EDMV3-33 | The ledger's existing "deferred" status value is never abolished, so the blocking predicate as specified silently excludes deferred findings -- a structural D13(a) bypass. A-03 | P0 | high | Feature Gaps / D13 fidelity | EDMV3-36, EDMV3-11, EDMV3-67 | Computed convergence cannot distinguish a partial (--lenses subset) round, so a 3-lens smoke audit can unlock approve-gate and archive. Evidence: `skills/code-audit/SKILL.md:54` ("Convergence check (full rounds only -- partial rounds are never convergent)") and EDMV3-67 AC 2 ("a partial round is never convergent, which the skill already enforces at line 54") preserve the rule. The mechanism that replaces prose is weaker than the prose it replaces. Fix: add to EDMV3-36: `audit-converged` also reads the latest `lenses-run.txt` / an `audit_rounds` round-type record and exits non-zero with "last round was partial (lenses: ...); a full round is required for convergence". ## Overall Verdict: FAIL (remediable)

This is a strong, unusually well-grounded SRD -- anchor fidelity is near-perfect across the roughly forty path:line references re-verified, the ID/priority arithmetic is exact, every epic traces to its workstream with no silent drops, and D2/D4/D14 are encoded faithfully. It fails Phase 3 on three classes of defect that must not reach ticket writing. First, the delivery plan contradicts its own dependency graph: Wave A's enforcement-kernel epic depends on three Wave B requirements, and shipping Wave A as specified strands any initiative with an open PARTIAL behind an archive refusal that points at a skill which does not yet exist (A-01). Second, and most seriously for the initiative's central promise, D13 is not fully converted from prose into mechanism: the ledger's legacy `deferred` status value survives untouched and slips straight through the new blocking predicate (A-02); `audit-converged` cannot tell a three-lens smoke round from a full round, so a partial audit can compute convergence and unlock both the human gate and archive (A-03); the vocabulary sweep's scan scope omits `hooks/hooks.json`, leaving `deferred-to-runtime` alive in a live prompt (A-05); and the compensating control for the dispatcher refactor is a Step 0 prose instruction that the SRD's own Tier model classifies as unenforceable while the Glossary calls it deterministic -- with three of the eight phase skills mapping to a `gate-check` branch that silently returns 0 anyway (A-04, A-09). Third, requirement quality has a systematic hole: six Must-Have requirements contain unresolved either/or decisions inside their acceptance criteria (A-06), six Must-Haves depend on Should-Haves (A-18), the highest-impact residual risk's only two mitigations are both Should (A-19), and several ACs are unfalsifiable or provably wrong against the tree on day one (A-21, A-12, A-10). None of this is architecturally fatal -- every P0 has a small, concrete fix, most of them a single added acceptance criterion -- but all eight P0s and the nineteen P1s should be closed and the SRD re-versioned before Gate 2, because each one would otherwise be discovered by an implementer holding a ticket that cannot be completed as written.
