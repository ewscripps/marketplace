# Lens L6: Documentation Accuracy -- Round 11

## Findings (L6: Documentation Accuracy)

**P2-1 -- The enforced 100KB eval budget has three docs and two mutually exclusive verdicts.** `plugins/edm/CLAUDE.md:1057` states the `lint:file-type-ban` job "sums all of `plugins/edm/evals/`, which is ~134KB and therefore over budget at HEAD". The same table row marks the job "Yes (blocking since EDMV3-T57 AC10 -- carries no `allow_failure`)", and `.gitlab-ci.yml:404-411` does `if [ "$evals_kb" -gt 100 ]; then ... exit 1`. So CLAUDE.md asserts a blocking `lint` job is red on every MR that touches the plugin. But `plugins/edm/evals/fixtures/tiny-svc/README.md:38-46` says the tree "stays under the 100KB budget for `plugins/edm/evals/` ... and fails the blocking `lint` stage above 100KB" (i.e. green), and `plugins/edm/evals/README.md:294` says "The fixture plus `expected.json` stays under 100KB". At most one of these is true; a contributor's belief about whether the plugin currently merges depends on which file they opened. Fix: single-source the verdict on the job's own emitted line (`file-type-ban: tracked plugins/edm/evals/ size OK (${evals_kb}KB, documented budget is 100KB)`) -- delete the standing pass/fail assertion from all three prose sites, and if the sum really exceeds 100KB say so plainly in CLAUDE.md plus name the resolution (narrow the sum to `plugins/edm/evals/fixtures/` per EDMV3-T22 AC3, or raise the constant at `.gitlab-ci.yml:404`). Confidence medium: no Bash in this lens, so the byte total was not measured independently -- the finding rests on the docs contradicting each other, which holds either way.

**P2-2 -- Scope conflation inside the bullet that exists to explain the scope.** `plugins/edm/evals/fixtures/tiny-svc/README.md:38-39` reads "The fixture plus `expected.json` stays under the 100KB budget for `plugins/edm/evals/`" -- a fixture-tree measurement asserted against the whole-tree budget. Lines 41-43 of the same bullet then correctly describe the enforcement as `git ls-files -- plugins/edm/evals` (driver and scorer included), so one bullet both distinguishes and collapses the two scopes that `plugins/edm/CLAUDE.md:1057` and `plugins/edm/evals/README.md:294-298` call an unresolved divergence. Fix: "The fixture plus `expected.json` is ~11KB. The enforced ceiling is 100KB over ALL git-tracked bytes under `plugins/edm/evals/` -- a strictly larger set that includes the driver and scorer (CA-463)."

**P2-3 -- A hand-maintained measured quantity in prose, with nothing pinning it.** The "~134KB" at `plugins/edm/CLAUDE.md:1057` is a byte total that changes with any fixture or baseline edit, and no test asserts it. This is the exact failure mode the same file refuses two hundred lines earlier: the `edm-lint-artifacts` row at `plugins/edm/CLAUDE.md:803` tells readers to run `--help` "rather than a count hardcoded here (a count drifts as classes are added)", and the schema-comment counts are pinned by computed assertions under the `G25/CA-342` banner in `bin/tests/wave7-smoke.sh`. Fix: replace the figure with the reproduction command already given at `plugins/edm/evals/README.md:297-298` (`git ls-files -- plugins/edm/evals`, never `du`), or pin it the way `G25/CA-342` pins its counts.
