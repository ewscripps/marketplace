## Findings (L5: Runtime Hygiene)

### L5-001 (P2) -- two `wave7-smoke.sh` cases fabricate session JSONL inside the invoking user's REAL `~/.claude/projects/`, cleaned up only on the success path

- **File type / where created:** synthetic Claude Code session-history directory + `*.jsonl` files, created by `stage_session_jsonl` (`/Users/darryl.porter/projects/marketplace/plugins/edm/bin/tests/_harness.sh:400-419`, which `mkdir -p`s its target) at `/Users/darryl.porter/projects/marketplace/plugins/edm/bin/tests/wave7-smoke.sh:7034-7036` (`g47_zero_case`) and `:7066-7069` (`g47_fallback_case`).
- **Why it lands outside the scratch root:** `session_dir_for_test_cwd` (`_harness.sh:390-392`) is `${HOME}/.claude/projects/$(pwd | tr '/.' '-')`. Both G47 subshells `cd` into a `$TMP` scratch dir but **never export a scratch `HOME`**, so `$HOME` is the invoking user's real home and the fabricated session dir materializes in the live Claude Code session store that `edm-state get_session_tokens_since` itself reads.
- **`.gitignore`:** N/A (outside the repo) -- so this is the "unexpected location" half of the lens, not the untracked half.
- **Accumulation risk:** `rm -rf "$sess_dir"` is the **last** statement inside each subshell. `wave7-smoke.sh` runs under `set -euo pipefail` and the fallback case's `out="$(bash -c ...)"` at `:7072` is unguarded, so any non-zero exit there -- or a Ctrl-C/SIGTERM at any point -- aborts the subshell before the cleanup line, stranding the directory permanently (the suite's own `$TMP` trap does not cover it). Verified empirically: `~/.claude/projects/*edm-*` and `*wave*` are currently clean, so this is latent, not yet realized. Residue would be inert (keyed to a scratch cwd that no longer exists), which is what holds this at P2 rather than P1.
- **Fails the "consistent pattern" filter:** every sibling site does the opposite -- the six wave6 sites (`wave6-smoke.sh:3400-3406, 3453-3459, 3573-3579, 3624-3630, 3708-3714`, plus `:923-929`) each export a `$TMP`-rooted `HOME` first, and the CA-160b site **in this same file** (`wave7-smoke.sh:5341-5362`) was fixed for exactly this defect. Its comment at `:5345-5349` now states something false: *"this used to derive sess_dir straight from the invoking user's REAL `$HOME` (the only bare `$HOME` reference in this suite)"* -- there are two more, added later by G47.
- **Fix:** inside each of the two subshells, `export HOME="$scratch"` (or a dedicated `mktemp -d "${TMP}/g47-home.XXXXXX"`) before calling `session_dir_for_test_cwd`, mirroring `wave7-smoke.sh:5350`; then correct the stale "only bare `$HOME` reference" claim at `:5345-5349`.

### L5-002 (P2) -- `edm-state`'s own directory-creating paths leave an initiative dir with no `.gitignore`, and the CA-169 comment asserts otherwise

- **File types / where created:** `.edm-state.json.bak` (`cp -p` in `_rmw_state_body`, `edm-state:705`), the never-unlinked flock file `.edm-state.lock` (`edm-state:1120`), the mkdir-spinlock `.edm-state.lockd/` + `pid` (`:1165, :1214`), and `write_atomic`'s `*.tmp.XXXXXX` staging files (`:631`) -- all inside the initiative directory.
- **`.gitignore`:** covered **only** when the directory was scaffolded by `edm-init`, whose unconditional block is at `/Users/darryl.porter/projects/marketplace/plugins/edm/bin/edm-init:169-174`. But `edm-init` is not the only creator: `cmd_init` does its own `mkdir -p "$(dirname "$f")"` (`edm-state:1807`) and `rmw_state` does the same (`edm-state:720`). `edm-state init <PREFIX>` is a publicly documented subcommand (`plugins/edm/CLAUDE.md:761` table, `edm-state --help`), so it is a second entry point that materializes an initiative directory with no ignore file, after which every one of the files above shows up untracked in `git status` on the consumer's host and is reachable by a `git add -A`.
- **Load-bearing incorrect claim:** `edm-state:1083-1087` justifies never unlinking the flock file with *"G38/CA-314: `edm-init` writes `.edm-state.lock*` into every initiative's own per-initiative `.gitignore` unconditionally, so this is not a leak in a consumer project either."* That holds for `edm-init`-created initiatives only; the same file's own `cmd_init`/`rmw_state` bypass it. `README.md:208-229` has the same edm-init-only framing.
- **Accumulation risk:** bounded per initiative (`.bak` and the lock names are overwritten/reused, tmp files are transient), so this is untracked-file noise plus accidental-commit exposure, not unbounded growth. Exposure is limited because every shipped skill invokes `edm-init` (`skills/orchestrator/SKILL.md:97,101`, `skills/plan/SKILL.md:77`, `skills/tickets/SKILL.md:140`) -- which is what holds it at P2.
- **Fix (either):** (a) move the four-line `.gitignore` write into `cmd_init` itself so both entry points are covered and `edm-init`'s copy becomes a redundant idempotent write; or (b) if `edm-state init` is meant to be internal-only, say so in its help text and in the `CLAUDE.md` subcommand table, and amend the `edm-state:1083-1087` and `README.md:215-217` claims to name the precondition.

### L5-003 (P2) -- fixture README instructs a write to a hardcoded, shared `/tmp/scores.json`

- **File type / where:** `/Users/darryl.porter/projects/marketplace/plugins/edm/bin/tests/fixtures/code-audit/README.md:49` documents `plugins/edm/evals/score-artifacts.sh plugins/edm/bin/tests/fixtures/code-audit/ --out /tmp/scores.json` as the copy-pasteable invocation.
- **Why it's a finding:** this is the one runtime-write instruction in the plugin that uses a bare `/tmp` path. Every executable in the tree uses `${TMPDIR:-/tmp}` (`edm-state:1117`, `edm-lint-artifacts:133,140`, `edm-check-grants:123`, `_harness.sh:75,101`, `evals/tiering-matrix.sh:147`, every suite's `TMP=`), and `wave7-smoke.sh:5320-5324` (G55/CA-215) fixed precisely this class in a test with the rationale that a hardcoded shared path "is never pre-cleaned ... and collides across two concurrent suite runs on one machine." A predictable, world-writable `/tmp/scores.json` is also plantable/symlinkable by another local user on a shared host. It also self-contradicts the prose three lines below it (`:52-54`, "point `--out` at a scratch path outside the plugin source tree").
- **Accumulation:** one file, overwritten; the concern is location and collision, not growth.
- **Fix:** `--out "${TMPDIR:-/tmp}/edm-scores.json"` in that example line.
