### Details

#### Finding 1 (P1): the CA-476 fix hand-rolls a column-1 fence tracker three times inside one function, in a file that already sources the project's single-sourced fence classifier -- and the copy has diverged on exactly the defect CA-009 and CA-019 were filed to close

- **File A (the new copies)**: `plugins/edm/bin/edm-state:5199-5242` -- `pattern_extract_titles`. Its `code`, `srd` and `qc` arms each open with the identical two lines:
  ```
  /^```/ { infence = 1 - infence; next }
  infence { next }
  ```
  at `:5205-5206`, `:5216-5217` and `:5228-5229`. Three byte-identical copies of a fence state machine, inside one function, added in the same commit.
- **File B (the canonical mechanism)**: `plugins/edm/bin/_edm-lint-lib.sh:104-190` (`build_line_classes`) delegating fence recognition to `plugins/edm/bin/edm-mermaid-rules.awk:120-150` (`mermaid_fence_run_len`, `mermaid_fence_lang`, `mermaid_is_fence_close`), exposed as `ignored_line_set` / `is_ignored_line` at `_edm-lint-lib.sh:209-212` and `:192-195`.
- **Divergence (three distinct behavioural differences, all in the unsafe direction)**:
  1. **Indented fences are invisible to the copy.** `mermaid_fence_run_len` de-indents before counting backticks (`edm-mermaid-rules.awk:120-126`, `sub(/^[[:space:]]+/, "", body)`), and the reason is documented at `:37-46` and `_edm-lint-lib.sh:27-30`: "real markdown often nests a fenced block under a numbered list step or a blockquote, and without stripping the leading whitespace before counting backticks, an indented fence is invisible to fence detection entirely". The copy's `/^```/` anchors at column 1. So a fenced example finding indented under a numbered step never toggles `infence`, and its `### CA-NNN ...` / `## G{N} ...` heading is harvested into the shipped pattern library **as if it were a real finding** -- which is precisely the pollution CA-476 (P1) was filed to stop, re-opened through a different door. This is the same divergence axis as CA-009 (P1, fixed round 2: "the two mirrored ignore-set copies anchor fences at column 1 while the canonical linter de-indents") and the same axis `edm-mermaid-rules.awk:22-26` records for `score-artifacts.sh` -- third occurrence of one class.
  2. **Variable-length fences desync the copy.** The canonical machine records the opener's run length (`_edm-lint-lib.sh:110`, `fence_len = mermaid_fence_run_len(line)`) and closes only on a run `>= fence_len` with nothing but whitespace after it (`mermaid_is_fence_close`, `edm-mermaid-rules.awk:145-150`). The copy toggles on *any* line beginning with three backticks. A four-backtick block quoting a three-backtick block -- the standard markdown idiom for showing fenced content, and a plausible shape in an audit report that quotes report formats -- inverts `infence` for the remainder of the file, after which every real finding heading is skipped. That direction loses findings silently rather than adding false ones; it now at least surfaces as `extraction_status: no-recognized-findings` (`:5251-5263`), so it is detectable, but it is still wrong.
  3. **`edm-lint-ignore` markers are honoured by the canonical mechanism (`_edm-lint-lib.sh:169-179`) and not by the copy.** Minor by comparison, but it means "ignored" means two different things in two halves of one command.
- **Why this is squarely L10 and not a style nit -- the comment asserts the parity it does not have**: `edm-state:5197-5198` reads "**Fence-aware throughout, for the same reason `pattern_insert_line_for` is (CA-056)**". `pattern_insert_line_for`, twenty lines below in the same file, uses the **shared** mechanism -- `_pif_ignored="$(ignored_line_set "$_pf" ...)"` at `:5300` then `is_ignored_line` at `:5305`, with its own docstring at `:5294-5296` naming "the shared `ignored_line_set`/`is_ignored_line` from `_edm-lint-lib.sh`". `_cmd_update_patterns_body:5363` uses the shared mechanism too. So within a single command, the **destination** file is classified by the canonical de-indenting classifier and the **source** report by a weaker hand-rolled one, under a comment claiming they are the same. That is the CA-343 / CA-420 / CA-505 class -- a comment asserting single-sourcing over a site that is not single-sourced -- at a fifth site, introduced by the fix for a P1.
- **False Alarm Filter**: (1) Not a justified difference. `edm-state` already sources `_edm-lint-lib.sh` at `:63` with the comment at `:56` naming exactly this purpose, and `_edm-lint-lib.sh:4-7` names `bin/edm-state` as one of its four consumers, and `:53-55` names edm-state's pattern-library machinery as an `ignored_line_set` caller by name (pinned by `wave7-smoke.sh:4903-4904`). There is no circular-dependency or portability reason. (2) Not test-only -- this is production `bin/` code reached by four skills. (3) Not intentional: nothing in the tree records a decision to use a weaker rule here, and the comment claims the opposite.
- **Test coverage confirms the gap is untested, not merely unnoticed**: the CA-476 block's only fence case is `wave7-smoke.sh:4048-4053`, a **column-1** ` ```markdown ` fence, asserted at `:4079-4080`.
