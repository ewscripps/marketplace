# Lens L2: Dead Code & Unreachable Paths -- EDMV4 ECC Integration, Round 1 (full)

Scope: `git diff main..HEAD -- plugins/edm/` on branch `edm/edmv4-ecc-integration`.
Primary surface: `bin/edm-gateguard`, `bin/edm-hookify`, `bin/edm-stop-gate`, `bin/edm-bash-gate`,
`bin/edm-repo-readiness`, `bin/_edm-datadir-lib.sh`, `bin/edm-state`, `hooks/hooks.json`,
`skills/*/SKILL.md`, `agents/*.md`.

**Method note.** This lens reports a path as dead only when a *named constraint* eliminates it, never
because nothing has exercised it yet. `EDMV4-62` establishes that neither `/plugin update` nor
`/reload-plugins` reads the working tree, so every hook consumer in this diff is unexercised; that
alone is not unreachability and is not reported as such. The constraints actually used below are:
Claude Code's documented `PreToolUse` matcher semantics; `SRD_ROOT`'s relative default at
`bin/edm-state:124`; the absence of any `.claude/edm-hookify/*.json` in the tree; `action` defaulting
to `warn` (`EDMV4-T42` AC2); `CONDITIONAL_LENS_IDS="L13"` at `bin/edm-state:1685`; and
`decisions.md` D26 (MultiEdit absent from this host's toolset).

and the `action: block` opt-in -- L2-005; (3) the marker-absent fast-allow path and what sits below

that cannot fail.
