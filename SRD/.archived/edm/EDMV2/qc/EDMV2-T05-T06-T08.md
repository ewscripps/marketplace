## EDMV2-T06: Harden write_handoff_internal Decisions-Made parsing for the unified template

### What was changed

No changes to `bin/edm-state` were required. The existing awk expression:
```
awk '/^## Decisions Made/{p=1;next} p && /^## /{p=0} p{print}'
```
already handles all required edge cases correctly.

### Fixture test results

Five fixture tests were run against the awk expression:

**Fixture 1 — plan-skill style (Decisions Made in middle, followed by ## Notes)**
```
Input:  ## Decisions Made\n- Which approach?: Option A\n- Auth method: OAuth2\n## Notes\n...
Output: - Which approach?: Option A\n- Auth method: OAuth2
Result: PASS — decisions extracted verbatim, Notes section not included
```

**Fixture 2 — orchestrator style (Decisions Made as final section, no trailing ##)**
```
Input:  ## Decisions Made\n- Which approach?: Option B\n- DB choice: PostgreSQL\n(EOF)
Output: - Which approach?: Option B\n- DB choice: PostgreSQL
Result: PASS — awk reads to EOF when no subsequent ## heading exists
```

**Fixture 3 — Empty Decisions Made section**
```
Input:  ## Decisions Made\n\n## Notes\n...
Output: (empty)
Result: PASS — empty output triggers fallback placeholder in write_handoff_internal
```

**Fixture 4 — List items with `- ` prefix preserved**
```
Input:  ## Decisions Made\n- item 1\n- item 2
Output: - item 1\n- item 2  (2 lines with - prefix)
Result: PASS — p{print} preserves list markers unchanged
```

**Fixture 5 — Parser stops at next ## heading**
```
Input:  ## Decisions Made\n\n## Notes\nSome notes
Output: (empty — no bleed from Notes)
Result: PASS — p && /^## /{p=0} stops extraction correctly
```

### Acceptance Criteria Verification

**AC-1**: planning.md from `plan` skill with populated Decisions Made → those decisions appear verbatim in HANDOFF.md
- PASS — Fixture 1 confirmed: decision lines extracted verbatim, including `- ` prefix and `Question: Answer` format

**AC-2**: planning.md from `orchestrator` with populated Decisions Made → same
- PASS — Fixture 2 confirmed: decisions extracted identically whether from plan or orchestrator skill

**AC-3**: Empty fallback placeholder appears ONLY when Decisions Made section is genuinely empty
- PASS — Fixture 3: empty section → empty awk output → `[[ -z "$decisions" ]]` triggers fallback `_(none recorded yet - decisions are captured at Gate 1)_`

**AC-4**: Parser stops at next `## ` heading, no bleed from following section
- PASS — Fixture 5: `p && /^## /{p=0}` resets flag at any line starting with `## `, preventing bleed

**AC-5**: Decision lines beginning with `- ` are preserved
- PASS — Fixture 4: `p{print}` outputs all lines as-is, including `- ` list markers

**AC-6**: planning.md with Decisions Made as final section (no trailing `## `) is still parsed to EOF
- PASS — Fixture 2: awk's `p{print}` continues until end of input when no `## ` reset triggers

**AC-7**: Analysis confirms the awk expression handles all AC-1 through AC-6 cases
- PASS — Explicit fixture tests for every case. No code change was needed.
