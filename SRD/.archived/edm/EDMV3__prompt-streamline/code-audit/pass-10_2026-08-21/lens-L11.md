### Details

#### Finding 1 (P2, high) -- CA-490 re-confirmed STILL OPEN: the `complete:false` handshake is still unreachable

- **What exists**: `plugins/edm/bin/edm-compare-eval` declares three named refusal conditions in its own help block (`:18-25`) and three of them are implemented -- condition 3 (`complete:false`) at `:70-78`, condition 1 (`scorer_version`) at `:80-87`, condition 2 (`dimensions_scored`) at `:89-97`.
- **What it's wired to**: the sole automated caller is `.gitlab-ci.yml:801`, the one-argument form, which takes the default baseline `${SCRIPT_DIR}/../evals/baseline/scores.json` (`edm-compare-eval:56`). That file **does not exist** -- `plugins/edm/evals/baseline/` contains only `README.md`. Execution therefore stops at the baseline-existence check at `:61-65` and returns exit 3; `.gitlab-ci.yml:804` maps 3 to `eval comparison: NOT ARMED` and leaves the arm. Candidate JSON validation (`:67`) and all three refusal conditions sit **below** that early return.
- **What CA-490 prescribed**: move candidate JSON validation and condition 3 **above** the baseline-existence check, because condition 3 reads only the candidate and needs nothing from the baseline. What actually landed is a *partial* reorder: condition 3 moved above conditions 1 and 2, but the whole block is still below `:61-65`. The core symptom CA-490 was filed for is untouched.
- **Live consequence (two false claims still shipping)**: `.gitlab-ci.yml:775-776` asserts "A partial run continues through scoring and comparison (`edm-compare-eval` REFUSES a `complete:false` candidate by name, exit 2)", and `plugins/edm/CLAUDE.md:1065` asserts the stub's `complete: false` is "visibly refused by `edm-compare-eval`". Neither can occur: on the partial path the arm prints NOT ARMED and exits 3. The job still fails at the end via the separate `.gitlab-ci.yml:808` arm, so the *outcome* is fail-closed -- but the mechanism two comments name is dead wiring, which is exactly the class CA-452 was filed against.
- **Fix**: move `edm-compare-eval:67` (candidate JSON validation) and `:70-78` (condition 3) above the baseline-existence check at `:61-65`. Exit 3 keeps its meaning for a candidate that is complete but has nothing to compare against, and the handshake fires today on an un-armed tripwire, which is the state CI is in and stays in until the live baseline capture happens. If the reorder is rejected, qualify both comments ("once a baseline is committed") so they stop describing a path that does not exist.

#### Finding 2 (P2, medium) -- the phase-6 sharded-QC accept path is only ever exercised against a filename no producer writes

- **What exists**: `plugins/edm/bin/edm-state:2551-2561` accepts phase 6 as complete when either `qc/qc-summary.md` or any `qc/qc-shard-*.md` is present. The comment at `:2553` states the intent is to cover the two post-CA-473 prefixes, and the `die` message at `:2561` enumerates exactly `qc-shard-impl-*.md` and `qc-shard-pass-*.md`.
- **What it's wired to**: the only positive fixture for that accept path is `plugins/edm/bin/tests/wave6-smoke.sh:1960-1965`, which writes `$TMP/SRD/T11SHARD/qc/qc-shard-01.md` -- the bare, unprefixed form. Post-CA-473 there is **no producer left in the plugin that writes that name**: `hooks/hooks.json:117` explicitly forbids it ("NEVER write a bare `qc/qc-shard-{NN}.md`"), and `skills/implement/SKILL.md:106,:110` write only `qc-shard-pass-{NN}.md`.
- **The break**: the assertion passes only because the glob at `:2557` is wider than the contract its own diagnostic states. Neither of the two shapes that are actually produced has a positive phase-complete assertion, so a future tightening of the glob to the two documented prefixes -- the obvious follow-on to CA-473 -- would keep this test green while breaking both real paths, and conversely a regression in either producer's prefix would not be caught here. The fixture is now the only writer in the repository of the shape it asserts.
- **Fix**: change `wave6-smoke.sh:1965` to write `qc/qc-shard-impl-07.md`, add a sibling case writing `qc/qc-shard-pass-01.md`, and assert phase 6 completes for each independently. Then either tighten `edm-state:2557` to `qc-shard-impl-*.md`/`qc-shard-pass-*.md` so the glob matches the diagnostic at `:2561`, or amend `:2561` to admit that the bare form is still accepted.
