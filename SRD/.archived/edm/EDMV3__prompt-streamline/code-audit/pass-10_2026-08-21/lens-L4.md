**P2 -- `plugins/edm/bin/tests/wave7-smoke.sh:8715` -- the brand-new CA-473 case reintroduces the CA-401 bare-capture shape, and the shape is load-bearing for the whole block**

`ca473_skill_lines="$(grep 'writes qc/qc-shard' "$ca473_skill_md" 2>/dev/null)"` is a bare command substitution with no `|| true`, under `set -euo pipefail`, in top-level (non-tested) position. The stderr redirect at `:8715` additionally discards the diagnostic that would explain it. Fix: route it through `count_matches`/`|| true` with an explicit non-empty floor asserted by name, matching the seed-zero-then-capture form the same file already uses.

**P2 -- `plugins/edm/bin/tests/wave7-smoke.sh:8729` -- the CA-473 disjointness assertion is a string inequality between two tokens, so it also passes when either extraction silently returns nothing**

`[[ "$ca473_hook_tok" != "$ca473_skill_tok" ]]` is the load-bearing assertion of the CA-473 fix. It is preceded by non-empty guards at `:8718-8723`, which is genuinely good practice and materially better than the class average -- but those guards `fail` and *continue*; they do not gate `:8729`. If `sed` at `:8712-8713` stops matching (a hooks.json prompt reword) while the skill side still extracts, `ca473_hook_tok` is empty, `"" != "qc-shard-pass-"` is true, and `:8729` reports "hook token ('') and skill token ('qc-shard-pass-') are disjoint namespaces" as a **PASS** -- the collision check has become vacuous while printing an empty token in its own success message. The positive control at `:8735-8739` does not cover this: it rewrites the *skill* token to equal `$ca473_hook_tok`, so with an empty `ca473_hook_tok` the control degenerates to `"" == ""` and passes too. Both the assertion and its control go green on a broken extraction. Fix: make `:8729` conditional on both tokens being non-empty (or `return`/`fail` early out of a wrapper function on an empty extraction) so an extraction regression cannot read as disjointness.

**P2 -- `plugins/edm/bin/tests/wave6-smoke.sh:869` and `:884`, `:902`, `:922`, `:938`, `:951` -- the CA-471/CA-477/CA-478 pass directories are hand-built, so the gate is proven only against a manifest layout no shipped code produced**

Every fixture for the completeness gate `mkdir -p`s `code-audit/pass-1_2026-08-16` and `printf`s `lenses-run.txt` by hand. The gate under test resolves the pass directory by the glob `pass-${round_num}_*` (`bin/edm-state`), and the *real* producer of both the directory and the manifest is `skills/code-audit/SKILL.md`'s Write instruction -- a prompt surface with no executable path, hence no test. That is a legitimate constraint, not the finding. The finding is that nothing anywhere pins the two shapes to each other: if the skill's manifest format changes (a different header line, a `L1 -- name` suffix form, a lens-per-comma line) the gate's `^L[0-9]+$` filter at `bin/edm-state:4550` silently `continue`s every line, `_missing` stays empty, the gate goes quiet, and all fourteen CA-471/CA-477/CA-478 assertions stay green because they exercise the hand-built shape only. The CA-478 cases (`:918-948`) are strong work -- unterminated final line and CRLF are exactly the right adversarial inputs for an agent-authored file -- which makes the absence of a format pin the remaining gap rather than a general weakness. Fix: add one assertion that the manifest-writing instruction in `skills/code-audit/SKILL.md` still specifies the `Round type:` header plus bare `L<N>` lines the parser requires, with a positive control that mutates the extracted instruction and turns red; or generate the fixture manifest from the literal quoted in the skill rather than from a `printf` in the test.

**P2 -- `plugins/edm/bin/tests/wave6-smoke.sh:911-912` -- the three-miss-class assertion is a substring check on a space-joined list, so it cannot detect over-reporting**

`check "... names all three miss classes" "for: L2 L3 L4" "$ca477class_out"` passes on any warn whose list *contains* that substring -- including `for: L1 L2 L3 L4`, i.e. a gate that also flags the one lens whose JSONL is present and valid (`:904-905`). Under-reporting is caught (that is the mutation CA-477 was filed for, and it is caught correctly); over-reporting -- a false-positive gate that downgrades every round to `partial` and blocks all convergence, the exact harm CA-477(a) enumerates in its own mutation (a) -- is not. `check` is documented substring containment at `_harness.sh:26-34`, and this suite has already been through three findings on that exact confusion (CA-312, CA-454, CA-458). Fix: assert the full warn's lens list by exact equality after extracting it (the `for: ` field is trivially isolable with `sed`), so the assertion pins the list rather than a prefix of it.

**P2 -- `plugins/edm/bin/tests/wave6-smoke.sh:894` and `:914` -- the two `round_type` reads use `.rounds[-1]` with no assertion that exactly one round exists, so a double-recording regression is invisible**

Both mutation-catching assertions read `jq -r '.audit_rounds.code.rounds[-1].round_type'`. `[-1]` on an empty array yields `null` (which fails, safely) but on a *two*-element array silently reads the second. If `audit-round-complete` ever appended a round instead of amending the started one -- a plausible regression in the same function the CA-471 gate now writes into -- `CA477FULL` would hold `[{full},{full}]` and `:894` would still pass, while the initiative's real round bookkeeping had doubled. One extra assertion (`.audit_rounds.code.rounds | length == 1`) per fixture closes it. Low blast radius, hence P2; raised because these two lines are now the only mutation detectors for the gate.

**P2 -- `plugins/edm/bin/tests/wave7-smoke.sh:8653` -- the CA-472 tripwire's comment filter is a GNU-only regex, and it is the only filter standing between the tripwire and its own false-negative**

`ca472_n="$(grep -v '^\s*#' "$ca472_f" | count_matches -- '-f <(cat')"`. `\s` is a GNU extension: on BSD `grep` (macOS, the documented primary development platform) it degrades to the literal `s*#`, so only column-0 `#` comments are filtered. Round 9 noted this as diagnostics-only on the grounds that the direction is toward a false *failure*; re-derived this round, that holds **only** while no indented comment in the three scanned files contains the needle. The asymmetry worth recording is that the same one-character portability bug in the opposite direction (a filter that widens) would make the tripwire silently unarmed, and nothing in the case asserts the filter's own behavior. Fix: use `^[[:space:]]*#`, which is POSIX and behaves identically on both greps. One character, and it removes a platform-dependent branch from a tripwire.
