## Findings (L5: Runtime Hygiene)

### L5-001 (P2, high) -- `plugins/edm/bin/edm-state:5341`: the last RETURN-only cleanup trap in the plugin, on the binary every hook fires

File type: transient awk input file holding the ignored-line set (`edm-pxt-ignored.XXXXXX` under `${TMPDIR:-/tmp}`).
Where created: `bin/edm-state:5340`, `_pxt_ignfile="$(mktemp "${TMPDIR:-/tmp}/edm-pxt-ignored.XXXXXX")" || return 1`, inside `pattern_extract_titles()`.
Trap armed: `:5341`, `trap 'rm -f "$_pxt_ignfile"' RETURN` -- **RETURN only**.
In `.gitignore`: N/A (TMPDIR), which is why no ignore pattern can mitigate it.
Accumulation risk: `bin/edm-state:54` is `set -euo pipefail`. An errexit-triggered abort inside this function -- the three `awk` invocations at `:5349`, `:5360`, `:5382` are unguarded -- terminates the process **without firing the function's RETURN trap**, because bash routes errexit to exit and runs EXIT traps only. An `INT`/`TERM`/`HUP` delivered while awk is parsing a large findings report does the same. `_pxt_ignfile` is declared `local` at `:5339`, so even a hypothetical process-wide EXIT trap could not reference it -- the exact scoping problem `tiering-matrix.sh` solved with `"${tmp:-}"`.
False-alarm filter: fails all three clauses -- not gitignore-coverable, not deleted on the abort paths, not tmpfs-backed.
Why this is a defect and not a house pattern: this is the **only** `RETURN` trap left anywhere in the plugin (whole-tree grep: one hit here, one at `tiering-matrix.sh:158`). The `tiering-matrix.sh` one is the *fixed* form -- RETURN sharing a four-arm EXIT/INT/TERM/HUP set, with `:148` stating verbatim that "RETURN-only leaked `$tmp` on a die (exit 2, no RETURN) or a SIGINT mid-self-test." That is a description of this site. CA-014 identified this exact shape, CA-481(a) finished converting it, and this site was never swept.
Reachability: `pattern_extract_titles` is on the `edm-state update-patterns` path (the Living-Library growth step invoked from `/edm:code-audit`), not on every hook fire -- which is what holds this at P2 rather than P1.
Fix: convert to the canonical four-arm form, keeping RETURN on the EXIT-equivalent arm and switching to `"${_pxt_ignfile:-}"` so a post-return EXIT firing does not trip `set -u`:
`trap 'rm -f "${_pxt_ignfile:-}"' RETURN EXIT` / `trap 'rm -f "${_pxt_ignfile:-}"; exit 130' INT` / `TERM`+`143` / `HUP`+`129`. Note this needs `_save_traps`/`_restore_traps` bracketing if it can run nested inside `with_state_lock` -- check the call path at `:5554` before applying.

### L5-002 (P2, high) -- `plugins/edm/bin/tests/wave7-smoke.sh:9640`: the brand-new CA-481(c) sweep cannot see an unquoted trap handler, or a RETURN-only trap

File type: N/A -- this is a coverage hole in the durability pin that round 10 filed as L5-005 and that has now landed.
Where: `_ca481_sweep()`'s awk body, `:9640-9664`. It matches trap lines with `/^[ \t]*trap[ \t]+[^ \t-]/` (`:9641`), then derives the signal list as **the text after the last quote character**:
```awk
nq = split(line, sq, "\x27"); sig = (nq >= 3) ? sq[nq] : ""
if (sig == "") { ndq = split(line, dq, "\""); sig = (ndq >= 3) ? dq[ndq] : "" }
```
Consequence: for a trap whose handler is a bare function name -- `trap cleanup EXIT` -- there is no quote of either kind, so `nq == 1` and `ndq == 1`, `sig` stays `""`, and `has_exit`/`has_int`/`has_term`/`has_hup` are all false. The line matches the regex, is processed, and contributes **nothing**: it is not flagged by `combined` mode, and it never sets `file_has_exit[FILENAME]`, so `no-hup` mode cannot report the file either.
Two live sites are in exactly that form today: `evals/run-eval.sh:276` (`trap cleanup EXIT`) and `bin/tests/wave6-smoke.sh:37` (`trap cleanup_wave6 EXIT`). Both files happen to pass today only because their *other* three arms are quoted (`trap 'cleanup; exit 129' HUP` at `run-eval.sh:279`, `wave6-smoke.sh:40`), which is what sets `file_has_hup`. Their EXIT traps are invisible.
The decisive evidence that this matters: **the historical CA-482 regression this sweep exists to prevent was, at `wave6-smoke.sh`, an unquoted-handler statement.** `:34`'s own comment reads "a single trap on all four signals cleaned up and RESUMED the suite" -- i.e. the pre-fix line was `trap cleanup_wave6 EXIT INT TERM HUP`. Re-introduce that today and `combined` mode passes silently. The sweep would catch the same regression written as `trap 'cleanup_wave6' EXIT INT TERM HUP` but not as `trap cleanup_wave6 EXIT INT TERM HUP` -- a one-character difference decides whether the tripwire fires.
Second blind spot, same root cause: a `RETURN`-only trap yields `sig = " RETURN"`, so `has_exit` is false and the site is invisible. That is precisely why L5-001 above survived into this round despite a sweep that names `bin/*` in scope and ran green.
Positive-control gap: both controls (`:9687`, `:9694`) use the single-quoted handler form, so neither exercises the unquoted path. The controls prove the checks are not vacuous; they do not probe this boundary.
Accumulation risk: meta -- this is the mechanism by which L5-001 survived and by which the CA-482 class can silently return.
Fix: derive the signal list positionally rather than by quote position -- strip the `trap` keyword, remove a quoted handler if the next token opens a quote, otherwise drop exactly one whitespace-delimited token -- then parse the remainder. Add two further positive controls: `trap cleanup EXIT INT TERM HUP` (unquoted combined) and a `trap 'rm -f "$x"' RETURN`-only file, and extend `no-hup` mode to treat a `RETURN` disposition as an EXIT-class cleanup for registration purposes.
