### Details

#### Finding 1 (P1, high) -- CA-515's remediation reached the surface that DESCRIBES the write, not the surface that PERFORMS it

- What exists: two surfaces name the threshold-shard filename. skills/implement/SKILL.md:107 and :111 (the orchestrating skill's pseudo-code) write qc/qc-shard-pass-w{wave_num:02d}-01.md and qc/qc-shard-pass-w{wave_num:02d}-{i+1:02d}.md, with a CA-515 rationale comment at :112-119 explaining that the wave component is what stops wave 2's single-shard pass from overwriting wave 1's verdicts.
- What it's wired to: the agent that actually creates the file. agents/edm-qc-auditor.md:81 -- its own "## Output Path" section, the operative instruction for the writing agent -- still reads "<initiative-dir>/qc/qc-shard-pass-{NN}.md, where {NN} is your shard ordinal N, zero-padded (e.g. qc-shard-pass-01.md)". No wave component, and the worked example is the exact colliding name. Two further surfaces agree with the agent, not the pseudo-code: skills/implement/SKILL.md:84-85 (the skill's own prose, 22 lines above its own contradicting pseudo-code) and plugins/edm/CLAUDE.md:107.
- What it should call: per plugins/edm/CLAUDE.md Sec."Intent-to-file index", an agent's own body is authoritative for how that agent reports. The producer is therefore instructed to write the pre-fix name, so the cross-wave clobber CA-515 was filed for is still live: wave 2's shard ordinal 1 lands on wave 1's qc-shard-pass-01.md and the loser's PASS/FAIL verdicts are lost silently (only PARTIAL survives, via record-partial-verdict).
- Aggravating factor -- the test suite now enforces the pre-fix name. bin/tests/wave7-smoke.sh:9387-9388 asserts the literal string qc/qc-shard-pass-{NN}.md is present in agents/edm-qc-auditor.md. That is the ordinal-only shape :9402-9404's own CA-515 positive control declares must NOT ship. The three CA-515 assertions at :9394-9399 all run against $ca473_skill_all, which :9378 defines as the contents of the skill file only. So the remediation and every durability assertion for it are scoped to the describing surface, while a separate live assertion pins the producing surface to the broken name. Fixing the agent file fails the suite today.
- Fix: update agents/edm-qc-auditor.md:81 to qc/qc-shard-pass-w{NN}-{MM}.md (wave, then shard ordinal), matching the skill's pseudo-code, and reword the worked example off qc-shard-pass-01.md. Update skills/implement/SKILL.md:84-85 and plugins/edm/CLAUDE.md:107 to the same shape. Then change wave7-smoke.sh:9388 to assert the wave-carrying token in the agent file, and extend the :9394-9399 CA-515 checks to run against the agent body as well as the skill, so the producer is covered by the same three assertions the describer is.

#### Finding 4 (P2, high) -- edm-check-grants checks grant-without-instruction for agents only, and two dead skill grants are live because of it

- Two live instances found by hand this round:

  - skills/implement/SKILL.md:8 grants TodoRead, the only occurrence of that token anywhere in the plugin. Cross-lens: L1 already carries this one (pass-10 lens-L1.md:154), so it is cited here as evidence for the structural gap, not double-counted as an L11 finding.

Keep it warning-only, exactly as the agent-side negative direction is (:31-32), so it never changes the exit code; the value is the visible line, not a block.

#### Finding 5 (P2, medium) -- the post-deploy write has no directory-creation step, though the grant for one is held

- What exists: skills/verify-runtime/SKILL.md:80 instructs writing ${INIT_DIR}/post-deploy/verification.md, and :8 grants Bash(mkdir *).
- What it's wired to: no mkdir instruction anywhere in the body. The single place a directory is mentioned is :49-50, and it is a prohibition ("do not create post-deploy/verification.md or its directory") governing the empty-map early exit, not the write path.
- Why this is a break and not just an unused permission: the plugin's own convention is to instruct the mkdir explicitly before writing into a subdirectory that may not exist. agents/edm-qc-auditor.md:87 ("Run mkdir -p <initiative-dir>/qc before writing.") and skills/code-audit/SKILL.md:62 (mkdir -p "${OUTPUT_DIR}", backed by the same Bash(mkdir *) grant) both do it. verify-runtime holds the identical grant and skips the step, so its post-deploy/ write depends on the host's Write tool creating parents -- an unstated dependency the two sibling surfaces deliberately do not take.
- Fix: add mkdir -p "${INIT_DIR}/post-deploy" as the first action of step 4(g) at :80, phrased as edm-qc-auditor.md:87 phrases it. This uses the existing grant and removes the finding from Finding 4's dead-grant list at the same time.

Scoring impact is nil in the penalising direction (dimension 6 known-gap-recall measures recall of the six; extra findings are not penalised), so this is fixture-maintainability, not a scoring defect.
- Fix: add a two-line comment to routes.js in the established form, stating that /health is intentionally unreachable (there is no dispatcher) and that this is deliberately not one of the six counted gaps -- mirroring queue.js:5-7.
