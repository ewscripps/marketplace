### Finding 1 detail
`cmd_audit_round_start` accepts `--lenses`, derives `round_type` (`full` when the set equals all eleven or when the flag is omitted, else `partial`), and persists it. `cmd_audit_converged` exits 1 with "last round was partial" on `round_type == "partial"`. The skill omits the flag unconditionally, on both the full and smoke paths; step 1 computes `LENS_SET`/`ROUND_TYPE` and nothing consumes them for state; step 8 writes them only into a human-readable `lenses-run.txt`. Repo-wide, the only `--lenses`-passing call sites are in `wave6-smoke.sh`.

Consequence: the headline guarantee -- "A partial round is never convergent, so a smoke audit cannot close an initiative -- enforced by `edm-state audit-converged`" -- **cannot fire**. A three-lens smoke round records `full` and can walk straight through `audit-converged` -> `approve-gate code-audit` -> `code_audit_converged: true` -> `archive`. P0 rather than P1 because this is the one enforcement the initiative was built to add, and it is inert at its only call site.

Fix: pass `--lenses "${LENS_SET_CSV}"`, all eleven explicitly on a full round (the helper already derives `full` from an eleven-member set, so it is safe and self-documenting). Add an assertion that the skill's `audit-round-start` line contains `--lenses` so the argument cannot silently fall out again.
