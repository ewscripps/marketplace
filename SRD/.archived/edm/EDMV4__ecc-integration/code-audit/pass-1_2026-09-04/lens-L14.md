# EDM Code Audit Lens L14: Behavioral Test Coverage -- Round 1 (full)

Scope: `git diff main..HEAD -- plugins/edm/` on branch `edm/edmv4-ecc-integration`.
Behaviour under audit: `bin/edm-gateguard`, `bin/edm-hookify`, `bin/edm-stop-gate`,
`bin/edm-bash-gate`, `bin/edm-repo-readiness`, `bin/_edm-datadir-lib.sh`, and the `cmd_*`
functions added to `bin/edm-state`. Test surface: `bin/tests/wave8-smoke.sh` (new),
`wave6-smoke.sh`, `wave7-smoke.sh`, plus the older suites.

Method note: where a gap looked total, I drove the behaviour by hand in a scratch directory to
separate "no test exists" from "the code is broken". Every finding below states which of the two
it is. Several candidate findings were withdrawn this way -- see `## Noted / Not Actionable`.

Overall posture: the suite is unusually strong on paired positive controls, filesystem-snapshot
proofs and real fixture-driven denials. The gaps that remain are concentrated in three shapes:
(1) one whole new binary that no test ever executes, (2) the two hookify events that are not
`file`, and (3) documented CLI/env inputs that only ever appear at their default value, so the
input-reading half of the code is unverified.
