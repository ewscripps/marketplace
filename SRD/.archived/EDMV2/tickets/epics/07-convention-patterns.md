# Epic 7 — Convention Enforcement (WS-K) and Living Audit Pattern Library (WS-L)

Generated From: srd.md v1.0.7

This epic delivers two workstreams. WS-K (EDMV2-74 through EDMV2-79) makes the plugin obey the marketplace hard rules in its own generated output: no AI-attribution trailers, no Unicode glyphs, no leaked tool tags, a shared ticket size legend and cross-cutting-AC template, a built-in two-lane ticket audit, and a lint hook. WS-L (EDMV2-80 through EDMV2-84, plus EDMV2-80a and EDMV2-80b) turns the seed pattern library at `plugins/edm-ai-development/docs/audit-patterns/` into a self-improving feedback loop: auto-updated after every audit round, updatable on demand, and loaded by the SRD-writer, ticket-writer, implementer, and planning template at write time so audit findings get pre-empted rather than re-discovered.

All implementation work targets the staging copy `plugins/edm-ai-development-staging/` per EDMV2-109 (C-5 self-hosting safety). Target Component paths below are written against the live plugin tree `plugins/edm-ai-development/` for clarity; during Phase 6 the developer edits the mirror of each path under `plugins/edm-ai-development-staging/`.

WS-K depends on the Epic 2 foundation (EDMV2-T24 through EDMV2-T54: `set-mode`, typed-set, file-locking, the round/ledger machinery, and the path-from-state helper). WS-L depends on the seed pattern library already existing (delivered as the EDMV2 seed step, present at the paths listed below) and on the WS-K lint infrastructure (EDMV2-T115) for ASCII/tag-clean appends.

Severity vocabulary referenced below is the unified scale from EDMV2-13 (P0/P1/P2 with P0 as blocking).
